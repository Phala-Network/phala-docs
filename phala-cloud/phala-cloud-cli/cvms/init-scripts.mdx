## Command: `phala cvms init-scripts`

### Syntax

```
phala cvms init-scripts [options] [<cvm_id>] [<slug>] [<state>]
```

### Description

Show or change the platform init scripts a CVM runs. With only a CVM, it lists the scripts. With a script name and `on` or `off`, it turns that script on or off and keeps the others as they are.

Turning a script on or off changes the CVM's compose, so the CVM restarts. See [Init scripts](/phala-cloud/cvm/advanced-settings#init-scripts).

### Arguments

| Argument | Description |
| -------- | ----------- |
| `<cvm_id>?` | CVM identifier (UUID, app_id, instance_id, or name) |
| `<slug>?` | Platform init script (`docker_cleanup`, `env_merge`) |
| `<state>?` | `on` or `off` |

Pass both `<slug>` and `<state>`, or neither.

### Options

| Option | Description |
| ------ | ----------- |
| `-y, --yes` | Replace custom init scripts. Without it, the command stops if the CVM has custom init scripts. |
| `--confirm-data-wipe` | Confirm turning on `docker_cleanup`, which erases container stores on every boot |

### Output

Without a script name, the command prints one row per script with the columns `SLUG`, `SELECTED`, `SELECTABLE`, and `REASON`. `SELECTED` says whether the CVM runs the script. `SELECTABLE` says whether you can turn it on, and `REASON` says why not. A last line tells you whether the CVM also runs custom init scripts.

If the script is already in the state you asked for, the command says so and changes nothing.

### Examples

* List init scripts

```bash
phala cvms init-scripts app_123
```

* Turn docker_cleanup on

```bash
phala cvms init-scripts app_123 docker_cleanup on --confirm-data-wipe
```

* Turn env_merge off

```bash
phala cvms init-scripts app_123 env_merge off
```
