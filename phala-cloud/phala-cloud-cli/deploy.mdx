### Command: `phala deploy`

#### Syntax

```
phala deploy [options]
```

#### Description

Deploy new CVM or update existing one

#### Options

| Option | Description |
| ------ | ----------- |
| `-n, --name <value>` | CVM name (defaults to directory name) |
| `-c, --compose <value>` | Path to Docker Compose file (default: docker-compose.yml) |
| `-t, --instance-type <value>` | Instance type (e.g., tdx.small, auto-selected if omitted) |
| `-r, --region <value>` | Preferred region (e.g., us-west, auto-selected if omitted) |
| `-e, --env <value>` | Environment variable (KEY=VALUE) or env file path (repeatable) |
| `--kms <value>` | KMS type: phala (default), ethereum/eth, or base |
| `--wait` | Wait for deployment/update completion |
| `--ssh-pubkey <value>` | SSH public key path (default: ~/.ssh/id_rsa.pub) |
| `--dev-os, --no-dev-os` | Use dev OS image (requires SSH key) |
| `--public-logs, --no-public-logs` | Make CVM logs publicly accessible (default: true) |
| `--public-sysinfo, --no-public-sysinfo` | Make CVM system info publicly accessible (default: true) |
| `--public-tcbinfo, --no-public-tcbinfo` | Make attestation data publicly accessible (default: true) |
| `--secure-time, --no-secure-time` | Enable secure time (default: false) |
| `--listed, --no-listed` | List CVM on the public Trust Center (default: false) |

#### Advanced Options

| Option | Description |
| ------ | ----------- |
| `--debug` | Enable debug logging |
| `--disk-size <value>` | Disk size with unit (e.g., 50G, default: 40GB) |
| `--fs <value>` | Filesystem for the data disk: zfs (default) or ext4. ext4 has lower I/O overhead; only zfs detects a modified block on the encrypted disk. |
| `--image <value>` | OS image version (auto-selected if omitted) |
| `--node-id <value>` | Node ID (auto-selected if omitted) |
| `--kms-contract <value>` | KMS contract address |
| `--kms-contract-id <value>` | KMS contract ID |
| `--key-provider-mode <value>` | Key provider mode: kms or local |
| `--experimental-key-provider-type <value>` | Set key_provider in compose (kms, local, tpm). Backend resolves key_provider_id for kms; local/tpm require manual key_provider_id. Computes and displays mr_config_id after provision. |
| `--skip-gateway` | Skip gateway matching |
| `--custom-app-id <value>` | Custom App ID (requires --nonce for PHALA KMS) |
| `--nonce <value>` | Nonce for deterministic app_id (requires --custom-app-id, PHALA KMS only) |
| `--pre-launch-script <value>` | Path to pre-launch script |
| `--runner <value>` | App runner: docker-compose (default), nerdctl-compose, or bash. With bash, --compose is the script to run. nerdctl-compose and bash need the compose_advanced feature. Create only. |
| `--app-compose <value>` | Path to a whole app-compose JSON file, sent instead of --compose and the compose flags. Needs the compose_advanced feature. Create only. |
| `--init-script <value>` | Platform init script to run on every boot: docker_cleanup or env_merge (repeatable). On update, replaces the current set. |
| `--clear-init-scripts` | Remove every platform init script from an existing CVM. Cannot be combined with --init-script. Update only. |
| `--launch-token <value>` | Launch token (at least 32 bytes) the CVM must boot with. Create only. |
| `--generate-launch-token` | Gate the CVM with a launch token Phala Cloud generates for a new app (shown once), or with the app's existing token. Create only. |
| `--launch-token-hash <value>` | Set requirements.launch_token_hash of an existing CVM to the hash printed by `phala apps launch-token set`; "" removes it. Update only. |
| `--event-log-version <value>` | Event log digest format: 1 or 2 (dstack OS 0.6.0+) |
| `--ephemeral-data-disk, --no-ephemeral-data-disk` | Format the data disk on every boot (dstack OS 0.6.3+). Turning it on for an existing CVM needs --confirm-data-wipe. |
| `--gateway, --no-gateway` | Route the CVM through the gateway (default: true) |
| `--confirm-data-wipe` | Confirm an update that turns on docker_cleanup or --ephemeral-data-disk, which erase data on every boot. Update only. |
| `--private-key <value>` | Private key for signing on-chain transactions (or set PRIVATE_KEY env var) |
| `--rpc-url <value>` | RPC URL for on-chain KMS transactions (or set ETH_RPC_URL env var) |
| `--prepare-only` | Prepare the update and generate a commit token. Skips all on-chain operations. Intended for multisig workflows. |
| `--commit` | Commit a previously prepared update using a commit token. Requires --token; --compose-hash and --transaction-hash are read from the token when omitted. |
| `--token <value>` | Commit token from a prepare-only update. |
| `--compose-hash <value>` | Compose hash from a prepare-only update. Optional in --commit mode when the token can provide it. |
| `--transaction-hash <value>` | Transaction hash proving on-chain compose hash registration. Pass `already-registered` to skip the proof and rely on state-only verification. |

#### Examples

* Deploy new CVM

```bash
phala deploy
```

* Deploy with environment variables

```bash
phala deploy -e NODE_ENV=production -e DEBUG=true
```

* Deploy with env file

```bash
phala deploy -e .env
```

* Deploy with specific instance type

```bash
phala deploy --instance-type tdx.medium
```

* Deploy to specific region

```bash
phala deploy --region us-west
```

* Deploy from a whole app-compose file

```bash
phala deploy --app-compose app-compose.json
```

* Deploy with a generated launch token

```bash
phala deploy --generate-launch-token
```

* Deploy with Ethereum KMS

```bash
phala deploy --kms ethereum --private-key <key> --rpc-url <url>
```

* Update existing CVM by ID

```bash
phala deploy --cvm-id app_abc123
```

* Update CVM with new compose file and env

```bash
phala deploy --cvm-id my-app --compose ./new-docker-compose.yml -e .env
```

* Update CVM and wait for completion

```bash
phala deploy --cvm-id app_abc123 --wait
```

On an update, `--wait` waits until the CVM is back in the state it had before: running, or stopped if it was stopped. It then checks the result of the update and fails if the update failed. This check is skipped when the CLI signs in with a GitHub Actions OIDC token. For a CVM that uses the `bash` runner, `--compose` (`-c`) sends the file as the CVM's `bash_script`.

* Update CVM from phala.toml

```bash
phala deploy
```

* Deploy with logs and sysinfo disabled

```bash
phala deploy --no-public-logs --no-public-sysinfo
```

* Deploy and list on Trust Center

```bash
phala deploy --listed
```

* Turn on container cleanup for an existing CVM

```bash
phala deploy --cvm-id app_123 --init-script docker_cleanup --confirm-data-wipe
```

* Update existing CVM to disable logs

```bash
phala deploy --cvm-id app_123 --no-public-logs
```

* Prepare update for multisig approval

```bash
phala deploy --cvm-id app_123 --prepare-only -c docker-compose.yml
```

* Commit a prepared update

```bash
phala deploy --cvm-id app_123 --commit --token <token> --compose-hash 0x... --transaction-hash 0x...
```
