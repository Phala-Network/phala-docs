title: CVM Configuration
description: Update Docker Compose files, environment variables, resources, visibility, and OS images on running CVMs.
---

Configuration methods let you modify a CVM after it has been provisioned. You can update the Docker Compose file, environment variables, resource allocation, visibility settings, and OS image independently.

<Warning>
**Every configuration update restarts the CVM.** The CVM is stopped, updated, and started again. The only exception is a compose change that matches what the CVM already runs: the API answers `no_change` and does nothing.
</Warning>

`patch_cvm` sends any set of changes in one request to `PATCH /cvms/{cvmId}`. `update_cvm_resources` and `update_cvm_visibility` send a subset of fields to the same endpoint. The other `update_*` methods call their own endpoints. See [Update CVM Configuration](/phala-cloud/update/update-cvm-configuration) for what each field does and which settings cannot change after create.

## update_docker_compose

`PATCH /cvms/{cvmId}/docker-compose`

Updates the Docker Compose configuration for a CVM. If the CVM has on-chain hash verification enabled, you need to pass `compose_hash` and `transaction_hash`.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | `str` | Yes | CVM identifier |
| `docker_compose_file` | `str` | Yes | Docker Compose YAML content |
| `compose_hash` | `str` | No | On-chain compose hash (if required) |
| `transaction_hash` | `str` | No | On-chain transaction hash (if required) |

**Returns:** `InProgressResponse` on success, or `ComposeHashPreconditionResponse` if on-chain verification is needed.

**Example:**

<CodeGroup>

```python Sync
result = client.update_docker_compose({
    "id": "my-app",
    "docker_compose_file": """
services:
  app:
    image: nginx:latest
    ports:
      - "80:80"
""",
})
```

```python Async
result = await client.update_docker_compose({
    "id": "my-app",
    "docker_compose_file": """
services:
  app:
    image: nginx:latest
    ports:
      - "80:80"
""",
})
```

</CodeGroup>

## update_cvm_envs

`PATCH /cvms/{cvmId}/envs`

Updates encrypted environment variables for a CVM. Environment variables must be encrypted using the KMS public key before being sent.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | `str` | Yes | CVM identifier |
| `encrypted_env` | `str` | Yes | Encrypted environment variable payload |
| `env_keys` | `list[str]` | No | List of environment variable keys |
| `compose_hash` | `str` | No | On-chain compose hash (if required) |
| `transaction_hash` | `str` | No | On-chain transaction hash (if required) |

**Returns:** `InProgressResponse` on success, or precondition response if on-chain verification is needed.

**Example:**

```python
from phala_cloud import encrypt_env_vars

# Encrypt env vars using KMS public key
pubkey_resp = client.get_app_env_encrypt_pub_key({
    "kms": "phala",
    "app_id": "my-app-id",
})

encrypted = encrypt_env_vars(
    env_vars=[{"key": "SECRET", "value": "my-secret"}],
    public_key=pubkey_resp.app_env_encrypt_pubkey,
)

client.update_cvm_envs({
    "id": "my-app",
    "encrypted_env": encrypted,
    "env_keys": ["SECRET"],
})
```

## commit_cvm_update

`POST /cvms/{cvmId}/commit-update`

Commit a prepared update using its token. `compose_hash` and `transaction_hash` are optional request fields. The returned `CommitCvmUpdateResult` contains `correlation_id` and `status`.

```python
result = client.commit_cvm_update({
    "cvm_id": "my-app",
    "token": token,
})
print(result.correlation_id, result.status)
```

The async client supports `await client.commit_cvm_update(...)`. A `safe_commit_cvm_update` variant is also available.

## update_cvm_resources

`PATCH /cvms/{cvmId}`

Changes the resource allocation (CPU, memory, disk, instance type) for a CVM.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | `str` | Yes | CVM identifier |
| `vcpu` | `float` | No | Number of vCPUs |
| `memory` | `float` | No | Memory in MB |
| `disk_size` | `float` | No | Disk size in GB. A disk cannot shrink. |
| `instance_type` | `str` | No | Instance type name |
| `allow_restart` | `bool` | No | Deprecated and not sent. The CVM restarts whenever a resize needs it. |

**Returns:** The API response, `{"message", "correlation_id", "status"}`.

**Example:**

<CodeGroup>

```python Sync
client.update_cvm_resources({
    "id": "my-app",
    "vcpu": 4,
    "memory": 4096,
    "instance_type": "tdx.medium",
})
```

```python Async
await client.update_cvm_resources({
    "id": "my-app",
    "vcpu": 4,
    "memory": 4096,
    "instance_type": "tdx.medium",
})
```

</CodeGroup>

## update_cvm_visibility

`PATCH /cvms/{cvmId}`

Controls which CVM information is publicly accessible.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | `str` | Yes | CVM identifier |
| `public_sysinfo` | `bool` | Yes | Whether system info is public |
| `public_logs` | `bool` | Yes | Whether logs are public |
| `public_tcbinfo` | `bool` | No | Whether TCB info is public |

**Returns:** `{"message", "correlation_id", "status"}`. `status` is `"in_progress"`, or `"no_change"` with an empty `correlation_id` when the settings already match.

These settings are part of the compose hash. For a CVM on Onchain KMS, the request fails with HTTP 465 until the new hash is registered on-chain. Use [`patch_cvm`](#patch_cvm), which returns the hash to register. The Trust Center listing is not a visibility setting; it has its own endpoint, `PATCH /cvms/{cvmId}/listed`.

**Example:**

```python
client.update_cvm_visibility({
    "id": "my-app",
    "public_sysinfo": True,
    "public_logs": False,
})
```

## patch_cvm

`PATCH /cvms/{cvmId}`

A batch update method that can modify multiple CVM fields in a single request. This is useful when you need to change several settings atomically.

`patch_cvm` does not send the API's `compose`, `init_scripts` and `confirm_data_wipe` fields yet. To use them, call [`PATCH /cvms/{cvmId}`](/phala-cloud/update/update-cvm-configuration) directly.

**Parameters:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | `str` | Yes | CVM identifier |
| `docker_compose_file` | `str` | No | Docker Compose YAML |
| `pre_launch_script` | `str` | No | Pre-launch script content |
| `allowed_envs` | `list[str]` | No | Allowed environment variable keys |
| `public_logs` | `bool` | No | Whether logs are public |
| `public_sysinfo` | `bool` | No | Whether system info is public |
| `public_tcbinfo` | `bool` | No | Whether TCB info is public |
| `encrypted_env` | `str` | No | Encrypted environment variables |
| `user_config` | `str` | No | User configuration string |
| `gpus` | `dict` | No | GPU assignment: `{"gpus": [{"slot": ..., "product_id": ...}], "attach_mode": ...}`. `attach_mode: "all"` attaches every GPU on the node. Other shapes fail validation. |
| `vcpu` | `int` | No | Number of vCPUs |
| `memory` | `int` | No | Memory in MB |
| `disk_size` | `int` | No | Disk size in GB |
| `instance_type` | `str` | No | Instance type, for example `tdx.medium` |
| `image` | `str` | No | OS image name |
| `shutdown_timeout` | `int` | No | Seconds to wait for a clean shutdown (10 to 1200) |
| `allow_force_stop` | `bool` | No | Skip the clean shutdown and stop the CVM at once |
| `prepare_only` | `bool` | No | Sent as the `X-Prepare-Only: true` header, not in the body. Also accepted as `prepareOnly`. |

**Returns:** A dict with `requires_on_chain_hash` (bool). When it is `False`, the dict has `correlation_id`. When it is `True`, it has `compose_hash`, `app_id`, `device_id` and `kms_info`, plus `commit_token`, `commit_url`, `api_commit_url` and `onchain_status` for a `prepare_only` call.

<Note>
On Onchain KMS, a change to the compose returns `requires_on_chain_hash: True`. Register `compose_hash` on-chain, then call `confirm_cvm_patch` with the compose hash and transaction hash. With `prepare_only`, anyone holding `commit_token` can finish the update instead. See [Multisig and Governance](/phala-cloud/key-management/multisig-governance).
</Note>

## Compose File Update Flow

For updates that require on-chain hash verification, the SDK provides a two-step flow similar to CVM provisioning:

### provision_cvm_compose_file_update

`POST /cvms/{cvmId}/compose_file/provision`

Provisions a compose file update and returns the new compose hash.

### commit_cvm_compose_file_update

`PATCH /cvms/{cvmId}/compose_file`

Commits the compose file update with the verified hash.

```python
# Step 1: Provision the update
provision = client.provision_cvm_compose_file_update({
    "id": "my-app",
    "app_compose": {
        "docker_compose_file": "services:\n  app:\n    image: nginx:latest",
    },
})

# Step 2: After on-chain verification, commit the update
client.commit_cvm_compose_file_update({
    "id": "my-app",
    "compose_hash": provision.compose_hash,
    "encrypted_env": "...",
    "env_keys": ["KEY1", "KEY2"],
})
```
