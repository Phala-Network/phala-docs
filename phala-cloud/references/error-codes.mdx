# Error Code Catalog

This document lists all error codes used by Phala Cloud API.

Error codes follow the format `ERR-{MODULE}-{CODE}` where:
- **MODULE**: Two-digit module identifier (01, 02, 03, ...)
- **CODE**: Three-digit sequential error number within the module

## Modules

- **Module 01** - CVM API / Preflight
- **Module 02** - Inventory
- **Module 03** - CVM Operations
- **Module 04** - Workspace
- **Module 05** - Credentials
- **Module 06** - Authentication (OAuth redirect errors — not returned as JSON API responses)
- **Module 17** - Log Access

## Module 01: CVM API / Preflight


| Error Code | Exception Class | Message |
|------------|----------------|---------|
| `ERR-01-001` | `NodeNotFoundError` | The requested node is not available<br/>*Raised when specified node is not found* |
| `ERR-01-002` | `ComposeFileRequiredError` | The request contains invalid parameters<br/>*Raised when compose_file is required but not provided* |
| `ERR-01-003` | `InvalidComposeFileError` | The Docker Compose file contains errors<br/>*Raised when Docker Compose file is invalid* |
| `ERR-01-004` | `DuplicateCvmNameError` | (dynamic: A CVM with name '...)<br/>*Raised when a CVM name already exists in the workspace (HTTP 409)* |
| `ERR-01-005` | `HashRegistrationRequired` | Compose hash registration required on-chain<br/>*Raised by an onchain KMS compose update when the new compose hash is not yet on DstackApp.allowedComposeHashes; the response carries commit_token, commit_url, and the on-chain action needed to complete the prepare-approve-commit flow (HTTP 465)* |
| `ERR-01-006` | `HashInvalidOrExpired` | The provided compose hash is invalid or has expired<br/>*Raised at commit time when the commit token is unknown, has expired (14-day TTL), has been superseded by a newer prepare for the same CVM, or the compose hash bound to the token no longer matches the compose file currently saved for this CVM — re-run prepare to recover (HTTP 466)* |
| `ERR-01-007` | `TxVerificationFailed` | Transaction verification failed<br/>*Raised at commit time when the supplied transaction_hash cannot be verified against the expected addComposeHash state change — the receipt is missing, the transaction reverted, or it did not target the expected DstackApp contract (HTTP 467)* |
| `ERR-01-008` | `HashNotAllowed` | The compose hash is not allowed by the on-chain contract<br/>*Raised at commit time when DstackApp.allowedComposeHashes(bytes32) returns false for the target hash — typically because the Phase 2 approval transaction has not actually landed on the expected contract, or landed on the wrong contract (HTTP 468)* |

| `ERR-03-008` | `ReplicaSourceInstanceNotAccessibleError` | The source CVM instance was not found in this workspace or access is denied<br/>*Raised when the replica source CVM instance is not visible in the current workspace (HTTP 404).* |

| `ERR-03-050` | `CvmAnnotationsVmmUnsupportedError` | (dynamic: The node runs dstack VMM ...)<br/>*The node's dstack VMM predates per-VM annotations (added in 0.6.1).* |
| `ERR-03-051` | `CvmAnnotationsVmmRequestFailedError` | (dynamic: The node could not read or update the CVM annotati...)<br/>*The node's VMM did not return or did not accept the CVM's annotations.* |
| `ERR-03-052` | `CvmDraftNotFoundError` | This CVM has no staged changes.<br/>*The CVM has no draft to show, apply or discard.* |
