<Note>
The Go SDK is currently in **beta**. The API surface may change between releases.
</Note>

The `phala` Go package provides a strongly-typed client for the Phala Cloud API. It handles authentication, automatic retries with exponential backoff, and structured error responses out of the box.

## Installation

Requires Go 1.25 or later.

```bash
go get github.com/Phala-Network/phala-cloud/go
```

## Quick Start

```go
package main

import (
	"context"
	"fmt"
	"log"

	phala "github.com/Phala-Network/phala-cloud/go"
)

func main() {
	client, err := phala.NewClient(
		phala.WithAPIKey("phak_your_api_key"),
	)
	if err != nil {
		log.Fatal(err)
	}

	user, err := client.GetCurrentUser(context.Background())
	if err != nil {
		log.Fatal(err)
	}
	fmt.Printf("Hello, %s!\n", user.User.Username)
}
```

## Client Creation

### `NewClient(opts ...Option) (*Client, error)`

Creates a new Phala Cloud API client. The API key is resolved from options first, then falls back to the `PHALA_CLOUD_API_KEY` environment variable. Returns an error if no API key is available.

```go
// Minimal — reads API key from PHALA_CLOUD_API_KEY env var
client, err := phala.NewClient()
```

```go
// Explicit configuration
client, err := phala.NewClient(
	phala.WithAPIKey("phak_your_api_key"),
	phala.WithBaseURL("https://cloud-api.phala.com/api/v1"),
	phala.WithTimeout(60 * time.Second),
	phala.WithMaxRetries(10),
)
```

## Configuration Options

Every option is a function passed to `NewClient`. They follow Go's functional options pattern, so you can combine as many as you need.

| Option | Default | Description |
|--------|---------|-------------|
| `WithAPIKey(key)` | `PHALA_CLOUD_API_KEY` env var | API key for authentication |
| `WithBaseURL(url)` | `https://cloud-api.phala.com/api/v1` | API base URL (or `PHALA_CLOUD_API_PREFIX` env var) |
| `WithAPIVersion(v)` | `"2026-06-23"` | API version header value |
| `WithTimeout(d)` | no timeout | HTTP client timeout as `time.Duration` |
| `WithMaxRetries(n)` | `30` | Maximum retries for retryable errors (409/429/503) |
| `WithHTTPClient(hc)` | `&http.Client{}` | Custom `*http.Client` for full control |
| `WithUserAgent(ua)` | `DefaultUserAgent()` | Replace the User-Agent header |
| `WithHeader(key, val)` | — | Add a custom header to all requests |

### User-Agent

By default the client sends `User-Agent: phala-cloud-sdk-go/<version> go/<v>`, for example `phala-cloud-sdk-go/0.5.0 go/1.24.2`. `phala.DefaultUserAgent()` returns this string. `WithUserAgent` replaces it entirely, so a value you supply overrides the default. To keep the SDK token and add your own, prepend to the default:

```go
client, err := phala.NewClient(
	phala.WithAPIKey("phak_your_api_key"),
	phala.WithUserAgent("my-automation/2.0 "+phala.DefaultUserAgent()),
)
```

## Environment Variables

| Variable | Description |
|----------|-------------|
| `PHALA_CLOUD_API_KEY` | API key for authentication |
| `PHALA_CLOUD_API_PREFIX` | Override base URL |

The client resolves environment variables automatically. If you pass an explicit option, it takes priority over the corresponding environment variable.

## Pointer Helpers

Many request structs use pointer fields for optional values. The SDK provides helper functions to make this ergonomic:

```go
phala.String("value")   // *string
phala.Int(4)            // *int
phala.Int64(100)        // *int64
phala.Float64(3.14)     // *float64
phala.Bool(true)        // *bool
```

These are especially useful when constructing request structs inline:

```go
&phala.PatchCVMRequest{
	PublicSysinfo: phala.Bool(true),
	VCPU:          phala.Int(4),
	Memory:        phala.Int(8192),
}
```

## CVM ID Resolution

The SDK automatically normalizes CVM identifiers before sending them to the API. You can pass any of the following formats to any method that accepts a `cvmID` string:

- **UUID** (with or without dashes) — dashes are stripped
- **40-char hex app ID** — `app_` prefix is added
- **Integer ID, hashed ID, or name** — used as-is

This means you never need to worry about converting between ID formats yourself.

## CVM Logs

Available in Go SDK v0.5.0 and later.

`FetchCVMLogs`, `FetchCVMLogEntries`, and `FollowCVMLogs` read serial, node, and container logs.

```go
// Last 100 lines of the serial console
text, err := client.FetchCVMLogs(ctx, "my-app",
	phala.LogSource{Type: "node", Channel: phala.CVMLogSerial},
	&phala.LogsOptions{Tail: 100},
)

// Follow the "api" container until ctx is cancelled
ctx, cancel := context.WithCancel(context.Background())
defer cancel()

lines, errs := client.FollowCVMLogs(ctx, "my-app",
	phala.LogSource{Type: "container", Name: "api"},
	&phala.LogsOptions{Tail: 50},
)
for line := range lines {
	fmt.Print(line)
}
if err := <-errs; err != nil {
	var apiErr *phala.APIError
	if errors.As(err, &apiErr) {
		fmt.Println(apiErr.ErrorCode, apiErr.Suggestions)
	}
}
```

```go
func (c *Client) FetchCVMLogs(ctx context.Context, cvmID string, source LogSource, opts *LogsOptions) (string, error)
func (c *Client) FetchCVMLogEntries(ctx context.Context, cvmID string, source LogSource, opts *LogsOptions) ([]LogEntry, error)
func (c *Client) FollowCVMLogs(ctx context.Context, cvmID string, source LogSource, opts *LogsOptions) (<-chan string, <-chan error)
```

`opts` may be `nil`.

| Method | Result |
|--------|--------|
| `FetchCVMLogs` | A `string`. For a container source, the SDK joins the entries into text. |
| `FetchCVMLogEntries` | `[]LogEntry` for a container source |
| `FollowCVMLogs` | A channel of log text and a channel of errors. Cancel with the `ctx` you pass in. |

`FollowCVMLogs` closes both channels when the follow ends. A cancelled context ends the follow without sending an error. Any other failure is sent once on the error channel. Read the log channel until it closes, then read the error channel.

**`LogSource`:**

| Field | Type | Description |
|-------|------|-------------|
| `Type` | `string` | `"node"` or `"container"`. Set it explicitly: any value other than `"container"` is treated as a node source. |
| `Channel` | `CVMLogChannel` | Node channel: `CVMLogSerial`, `CVMLogStdout`, or `CVMLogStderr` |
| `Name` | `string` | Container name or ID prefix. If empty, the SDK uses the first container that has a log endpoint. |

**`LogsOptions`:**

| Field | Type | Description |
|-------|------|-------------|
| `Tail` | `any` | Number of most recent lines as an `int`, or the string `"all"`. When `nil`, the server default applies. |
| `Since` | `any` | Start time as Unix seconds (`int`, `int64`, or a numeric string), an RFC 3339 string, or a relative duration such as `"10m"` (`s`, `m`, `h`, `d`). Container logs only; from v0.5.1 a node source with `Since` returns an error. |
| `Until` | `any` | End time. Same formats as `Since`. Container logs only; from v0.5.1 a node source with `Until` returns an error. |
| `Timestamps` | `bool` | Keep the timestamp prefix on container lines. Container logs only; from v0.5.1 a node source with `Timestamps` returns an error. |
| `ANSI` | `bool` | Keep ANSI color codes. |
| `Format` | `string` | `"text"` or `"ndjson"`. From v0.5.1, `FetchCVMLogEntries` reads it (default `"ndjson"`; other values return an error) and a node source with `"ndjson"` returns an error. `FetchCVMLogs` always returns text. |

`LogEntry` has two fields: `Channel` (`"stdout"` or `"stderr"`) and `Message`.

**Behavior:**

- Every connection uses a fresh signed URL.
- Follow mode reconnects after any stream end and gives up after 5 consecutive failures.
- Node heartbeat lines are dropped.
- Container follow resumes from the last timestamp without repeating lines.
- The helpers request CVM info with API version `2026-01-21` internally, so they work with clients configured for older versions.

For the HTTP details behind these methods, see [Fetch Logs over HTTP](/phala-cloud/monitoring/log-api).

**Errors:**

Log gateway errors are returned as `*APIError`. Check `ErrorCode` for a log error code such as `ERR-17-005`, and use `errors.As` to reach it. `Suggestions` holds suggested fixes from the API.

Container logs require [Public Logs](/phala-cloud/monitoring/public-logs) to be enabled on the CVM. When it is off, the method returns an `*APIError` with `ErrorCode` `ERR-17-006` ("Container logs are disabled") before sending any log request; this needs Go SDK v0.5.1 or later (v0.5.0 returned a plain error). Node channels are not affected. See [Fetch Logs over HTTP](/phala-cloud/monitoring/log-api#errors) for the full error code list.
