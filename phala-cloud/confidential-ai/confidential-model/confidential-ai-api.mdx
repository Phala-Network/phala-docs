## Overview

The on-demand Private AI API provides an OpenAI-compatible interface for confidential inference. Requests go through Phala's ACI gateway at `https://inference.phala.com/v1`. The gateway runs in a TEE, publishes an attestation report, and signs a per-response receipt that you can verify.


## Prerequisites

Private AI is paid from your workspace Balance, the same Balance that pays for CVMs and GPU instances. There is no separate top-up and no minimum: if your Balance has money, the API works. Gifted credits do not pay for Private AI.

In the dashboard, go to **Private AI** → **API Keys** and create your first API key. Click the key to copy it.

Once you get the API Key, you can start making requests to the Private AI API.

## Make Your First Request

Replace `<API_KEY>` with your actual API key. The examples below use `z-ai/glm-5.3`; use [List Models](/phala-cloud/confidential-ai/confidential-model/api-reference/models) to choose a model for your workload.

<CodeGroup>
```python Python
# Install OpenAI SDK: `pip3 install openai`

from openai import OpenAI

client = OpenAI(
    api_key="<API_KEY>",
    base_url="https://inference.phala.com/v1",
)

response = client.chat.completions.create(
    model="z-ai/glm-5.3",
    messages=[
        {"role": "system", "content": "You are a helpful assistant"},
        {"role": "user", "content": "What is your model name?"},
    ],
)

print(response.choices[0].message.content)
```

```typescript TypeScript
import OpenAI from 'openai';

const client = new OpenAI({
  baseURL: 'https://inference.phala.com/v1',
  apiKey: '<API_KEY>',
});

async function main() {
  const completion = await client.chat.completions.create({
    model: 'z-ai/glm-5.3',
    messages: [
      {
        role: 'user',
        content: 'What is the meaning of life?',
      },
    ],
  });
  console.log(completion.choices[0].message);
}

main();
```

```bash CLI
curl -X 'POST' \
  'https://inference.phala.com/v1/chat/completions' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer <API_KEY>' \
  -d '{
  "messages": [
    {
      "content": "You are a helpful assistant.",
      "role": "system"
    },
    {
      "content": "What is your model name?",
      "role": "user"
    }
  ],
  "model": "z-ai/glm-5.3"
}'
```
</CodeGroup>

The response is a standard OpenAI chat completion. In raw HTTP responses, Phala also returns verification headers:

| Header | Meaning |
| --- | --- |
| `x-receipt-id` | Receipt id for this response. Use it with `GET /v1/aci/receipts/{id}`. |
| `x-aci-keyset-digest` | Digest of the gateway keyset used for receipt verification. |

## Inspect the Response Receipt

Fetch the receipt with the `x-receipt-id` header:

```bash
curl -s "https://inference.phala.com/v1/aci/receipts/$RECEIPT_ID" \
  -H "Authorization: Bearer <API_KEY>" | \
  jq '.event_log[] | select(.type=="upstream.verified") | {model_id, result, required, session_id}'
```

On this TEE-only endpoint, successful upstream verification records `result: verified` and `required: true`; a failed required check refuses forwarding. This command only inspects the receipt. Ordinary SDK clients and cURL do not verify the gateway or each response. For client-side verification, use the [TypeScript ACI verifier](/phala-cloud/confidential-ai/verify/typescript-sdk) or [Private AI Proxy](/phala-cloud/confidential-ai/agents/private-ai-proxy).

## Choose a Model

The live catalog is authoritative; query it before hardcoding model IDs:

```bash
curl https://inference.phala.com/v1/models
```

The catalog is public and authoritative for availability, pricing, context limits, modalities, and
capabilities. Embedding models are listed separately at `GET /v1/embeddings/models`.

<Note>
Every model served at this Phala endpoint uses the TEE-only policy. Provider evidence covers different boundaries; inspect the cited session and apply the claims your policy requires. The catalog describes capabilities, while a verified receipt and session bind a specific exchange.
</Note>

<Note>
Confidential inference and zero data retention are separate properties. `is_tee` constrains who can read memory during execution. `zdr` constrains whether the upstream stores prompt or completion content after serving. Use [`GET /v1/models?zdr=true`](/phala-cloud/confidential-ai/confidential-model/api-reference/models#query-parameters) and `provider: {"zdr": true}` when retention is part of your policy.
</Note>

## Verify Your AI is Running Securely

The verification client checks a fresh [attestation report](/phala-cloud/confidential-ai/confidential-model/api-reference/attestation), recomputes the JCS keyset digest, checks its expiry and measured compose, and pins TLS before traffic. After the response it checks the [receipt](/phala-cloud/confidential-ai/confidential-model/api-reference/receipts) signature, `workload_keyset_digest`, exact request/response `body_hash` values, and cited upstream session. See [Verify a Response](/phala-cloud/confidential-ai/verify/verify-signature).

The legacy [Signature](/phala-cloud/confidential-ai/confidential-model/api-reference/signature) endpoint remains available for older clients, but new integrations should use `GET /v1/aci/receipts/{id}`.

## Billing

Private AI usage is charged to your workspace Balance. The response's `usage.cost` reports the request charge in USD when present. Token prices are published in the live catalog. Cached input tokens are charged at `pricing.input_cache_read` when a model exposes that rate, otherwise at its normal prompt rate; see [Prompt Caching](/phala-cloud/confidential-ai/confidential-model/prompt-caching).
