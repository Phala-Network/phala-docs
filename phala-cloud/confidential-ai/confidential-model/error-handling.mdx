The Phala host is TEE-only: unknown or non-TEE models return `404`. No request option relaxes the endpoint policy.

Account quota or API key budget exhaustion returns `402 insufficient_quota`. Check the Phala dashboard for workspace Balance and key limits.

## SDK Handling

```python
import os
from openai import OpenAI, AuthenticationError, RateLimitError, APIStatusError

client = OpenAI(
    base_url="https://inference.phala.com/v1",
    api_key=os.environ["PHALA_AI_API_KEY"],
)

try:
    response = client.chat.completions.create(
        model="z-ai/glm-5.3",
        messages=[{"role": "user", "content": "Hello"}],
    )
except AuthenticationError:
    print("Invalid API key")
except RateLimitError:
    print("Rate limited; retry with backoff")
except APIStatusError as e:
    print(f"API error {e.status_code}: {e.message}")
```

## Retry Policy

Retry only transient errors:

- Retry `429`, `500`, `502`, and `503` with exponential backoff.
- Do not retry `400` or `401` until you fix the request or key.
- For `412 session_not_accepted`, refresh and verify an accepted session before retrying; do not retry the same stale pin.
- If a confidential upstream verification fails, treat it as a failed security condition, not a normal retry loop, unless the API response documents it as transient.

```python
import time
from openai import RateLimitError, APIError

def with_retry(call, max_retries=3):
    for attempt in range(max_retries):
        try:
            return call()
        except (RateLimitError, APIError) as e:
            status = getattr(e, "status_code", 500)
            if status in (429, 500, 502, 503) and attempt < max_retries - 1:
                time.sleep(2 ** attempt)
                continue
            raise
```

## Common Cases

<AccordionGroup>
  <Accordion title="Invalid API key">
    Confirm the `Authorization: Bearer $PHALA_AI_API_KEY` header, check for whitespace, and create a fresh key from the Phala dashboard if needed.
  </Accordion>
  <Accordion title="Unknown model">
    List valid model ids with [`GET /v1/models`](/phala-cloud/confidential-ai/confidential-model/api-reference/models). Do not assume a model id exists until it appears in the catalog.
  </Accordion>
  <Accordion title="No zero-data-retention route">
    A request with `provider: {"zdr": true}` returns `404` when the selected model has no available zero-data-retention route. Query [`GET /v1/models?zdr=true`](/phala-cloud/confidential-ai/confidential-model/api-reference/models#query-parameters) before sending sensitive prompts that require this property.
  </Accordion>
  <Accordion title="Unsupported parameter">
    Parameter support depends on the model and serving route. The catalog advertises `supported_parameters`; handle unsupported-parameter errors returned by the request rather than assuming every advertised combination works.
  </Accordion>
  <Accordion title="Rate limited">
    Back off and retry. For sustained high volume, use dedicated GPU TEE capacity.
  </Accordion>
  <Accordion title="Upstream unavailable">
    Retry after backoff or choose another model. For sensitive prompts, confirm the replacement model returns `upstream.verified.result = verified`.
  </Accordion>
</AccordionGroup>

## Best Practices

- Branch on HTTP status and `error.type`, not message text.
- Keep API keys in environment variables or a secret manager.
- Never log request bodies for sensitive prompts.
- Verify `x-receipt-id` when the response is security-sensitive.
