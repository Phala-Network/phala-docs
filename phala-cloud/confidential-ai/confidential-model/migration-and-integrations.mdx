Phala Private AI is OpenAI-compatible. Most integrations require changing only the base URL and API key:

```text
https://inference.phala.com/v1
```

After migration, responses can be verified with `x-receipt-id`, [Attestation Report](/phala-cloud/confidential-ai/confidential-model/api-reference/attestation), and [Get Receipt](/phala-cloud/confidential-ai/confidential-model/api-reference/receipts).

## Migrate from OpenAI

```python
from openai import OpenAI

# Before
openai_client = OpenAI(api_key="sk-...")

# After
phala_client = OpenAI(
    api_key="YOUR_PHALA_API_KEY",
    base_url="https://inference.phala.com/v1",
)
```

Everything else stays familiar: chat completions, streaming, tool calling, vision, structured output, and embeddings use OpenAI-compatible request shapes.

## Migrate from OpenRouter

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://inference.phala.com/v1",
    api_key="YOUR_PHALA_API_KEY",
)
```

Model ids use the provider/model format returned by `/v1/models`. Verify the actual response receipt when you need evidence for an exchange.

## OpenAI SDK

<CodeGroup>

```python Python
from openai import OpenAI

client = OpenAI(
    api_key="YOUR_PHALA_API_KEY",
    base_url="https://inference.phala.com/v1",
)

response = client.chat.completions.create(
    model="z-ai/glm-5.2",
    messages=[{"role": "user", "content": "Explain TEE privacy."}],
)

print(response.choices[0].message.content)
```

```typescript TypeScript
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.PHALA_AI_API_KEY,
  baseURL: "https://inference.phala.com/v1",
});

const response = await client.chat.completions.create({
  model: "z-ai/glm-5.2",
  messages: [{ role: "user", content: "Explain TEE privacy." }],
});
```

</CodeGroup>

## LangChain

```python
from langchain_openai import ChatOpenAI

chat = ChatOpenAI(
    model="z-ai/glm-5.2",
    api_key="YOUR_PHALA_API_KEY",
    base_url="https://inference.phala.com/v1",
)

response = chat.invoke("Explain confidential inference in one paragraph.")
print(response.content)
```

## Vercel AI SDK

```typescript
import { generateText } from "ai";
import { createOpenAI } from "@ai-sdk/openai";

const phala = createOpenAI({
  apiKey: process.env.PHALA_AI_API_KEY,
  baseURL: "https://inference.phala.com/v1",
});

const { text } = await generateText({
  model: phala("z-ai/glm-5.2"),
  prompt: "Explain attestation.",
});
```

## Gateways

### Cloudflare AI Gateway

In **Compute & AI → AI Gateway → Custom Providers → Add Custom Provider**, set **Provider Name** to `Phala`, **Provider Slug** to `phala`, and **Base URL** to `https://inference.phala.com`, then save and enable the provider. Cloudflare's [custom-provider routing](https://developers.cloudflare.com/ai-gateway/configuration/custom-providers/) appends the path after `custom-phala/`, so the request includes `/v1/chat/completions`. For authenticated gateways, also send `cf-aig-authorization`:

```bash
curl "https://gateway.ai.cloudflare.com/v1/$CLOUDFLARE_ACCOUNT_ID/$CLOUDFLARE_GATEWAY_ID/custom-phala/v1/chat/completions" \
  -H "Authorization: Bearer $PHALA_AI_API_KEY" \
  -H "cf-aig-authorization: Bearer $CF_AIG_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "z-ai/glm-5.2",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

### LiteLLM

Add this model to your LiteLLM proxy `config.yaml` using its [generic OpenAI-compatible route](https://docs.litellm.ai/docs/providers/openai_compatible). Set `PHALA_AI_API_KEY` in the proxy's environment and start it with `litellm --config config.yaml`:

```yaml
model_list:
  - model_name: phala-glm
    litellm_params:
      model: openai/z-ai/glm-5.2
      api_base: https://inference.phala.com/v1
      api_key: os.environ/PHALA_AI_API_KEY
```

Clients of the proxy use `phala-glm` as their model name; LiteLLM sends `z-ai/glm-5.2` to Phala.

## Migration Checklist

- [ ] Create a Phala API key.
- [ ] Change the base URL to `https://inference.phala.com/v1`.
- [ ] List models with `GET /v1/models`.
- [ ] Use a catalog model; every model on this endpoint runs in a TEE.
- [ ] Capture `x-receipt-id` in raw HTTP responses when you need verification.
- [ ] Verify one representative response before production rollout.
