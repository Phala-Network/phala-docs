## URL Patterns

| Pattern | Protocol | Example |
|---------|----------|---------|
| `{app-id}.{cluster}.phala.network` | HTTP/HTTPS to port 80 (default) | `abc123.dstack-prod5.phala.network` |
| `{app-id}-{port}.{cluster}.phala.network` | HTTP/HTTPS (TLS termination) | `deadbeef111111111111111111111111-8080.dstack-prod5.phala.network` |
| `{app-id}-{port}g.{cluster}.phala.network` | gRPC/HTTP2 | `deadbeef111111111111111111111111-50051g.dstack-prod5.phala.network` |
| `{app-id}s.{cluster}.phala.network` | TLS passthrough to port 443 (default) | `abc123s.dstack-prod5.phala.network` |
| `{app-id}-{port}s.{cluster}.phala.network` | TLS passthrough | `deadbeef111111111111111111111111-5432s.dstack-prod5.phala.network` |
| `{app-id}-22.{cluster}.phala.network` | SSH tunnel | `deadbeef111111111111111111111111-22.dstack-prod5.phala.network` |

**Default Port Behaviors:**

- No port specified = routes to port 80 for HTTP or port 443 for TLS passthrough
- All external connections use port 443 regardless of internal port
- `{app-id}` is auto-generated on deployment
- `{port}` matches your container's exposed port
- `{cluster}` is regional (us, eu, asia)

## Auto-populated Environment Variables

You can use these variables in your docker-compose file:

| Variable | Value | Example |
|----------|-------|---------|
| `DSTACK_APP_ID` | Application identifier | `abc123def456` |
| `DSTACK_GATEWAY_DOMAIN` | Regional domain | `us.phala.network` |

## Environment Variables

The variables you can change to config networking features.

### SSH Access

| Variable | Type | Purpose |
|----------|------|---------|
| `DSTACK_ROOT_PASSWORD` | string | Root password inside the CVM (dev images only). SSH rejects it since dstack 0.5.6 |
| `DSTACK_ROOT_PUBLIC_KEY` | string | SSH public key (dev images only) |

### Custom Domains

A deployment uses either `DOMAIN` with `TARGET_ENDPOINT`, or `DOMAINS` with
`ROUTING_MAP`.

| Variable | Default | Purpose |
|----------|---------|---------|
| `DOMAIN` | Empty | Single certificate name; one leading `*.` is supported with DNS-01 |
| `TARGET_ENDPOINT` | Empty | Single backend as `host`, `host:port`, or an accepted URL form |
| `DOMAINS` | Empty | Comma- or newline-separated certificate names |
| `ROUTING_MAP` | Empty | Comma- or newline-separated `domain=backend:port` SNI routes |
| `GATEWAY_DOMAIN` | Empty | DNS alias target, for example `gateway.dstack-prod5.phala.network` |
| `APP_ID` | Guest agent app ID | Optional DNS-01 routing identity override |
| `PORT` | `443` | Public HAProxy and gateway routing port |
| `ALPN` | Empty | Comma-separated TLS protocols, such as `h2,http/1.1` |
| `CHALLENGE_TYPE` | `dns-01` | ACME mode: `dns-01` or `tls-alpn-01` |
| `ACME_EMAIL` | Empty | Optional public ACME contact; `CERTBOT_EMAIL` is a historical alias |
| `ACME_STAGING` | `false` | Use Let's Encrypt staging; `CERTBOT_STAGING` is an alias |
| `ACME_DIRECTORY_URL` | Let's Encrypt production | Custom directory for direct DNS-01 issuance |
| `RENEW_INTERVAL` | `43200` | Seconds between certificate checks |
| `EVIDENCE_SERVER` | `true` | Serve evidence through the HTTP/1.1 `/evidences/` handler |
| `EVIDENCE_PORT` | `80` | Internal evidence HTTP server port |
| `EVIDENCE_DIR` | `/evidences` | Evidence output directory |
| `SET_CAA` | `false` | Request CAA creation in direct DNS-01 mode |
| `TXT_PREFIX` | `_dstack-app-address` | Gateway routing TXT label prefix |
| `DELEGATION_ZONE` | Empty | Enable full DNS delegation for DNS-01 |
| `DETERMINISTIC_TLS_KEY` | `false` | Derive the direct DNS-01 TLS key through the current dstack socket |
| `MAXCONN` | `4096` | HAProxy connection limit |
| `TIMEOUT_CONNECT` | `10s` | Backend connection timeout |
| `TIMEOUT_CLIENT` | `86400s` | Client timeout |
| `TIMEOUT_SERVER` | `86400s` | Backend timeout |

URL schemes in `TARGET_ENDPOINT` and `ROUTING_MAP` are removed after parsing.
HAProxy forwards a decrypted raw TCP stream, so `https://` does not enable
backend TLS and URL paths are discarded.

### DNS Provider Credentials

| Provider | Variables | Required Permissions |
|----------|-----------|---------------------|
| Cloudflare | `CLOUDFLARE_API_TOKEN` | Zone:Read, DNS:Edit |
| Linode | `LINODE_API_TOKEN` | Domains:Read/Write |
| Namecheap | `NAMECHEAP_USERNAME`, `NAMECHEAP_API_KEY`, `NAMECHEAP_CLIENT_IP` | API enabled |
| Route53 | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_ROLE_ARN`, `AWS_REGION` | AssumeRole plus hosted-zone read/write |

Set `DNS_PROVIDER` to `cloudflare`, `linode`, `namecheap`, or `route53`.
Credential-based detection follows that order when the variable is omitted.

### TLS-ALPN-01 DNS Setup

| Variable | Default | Purpose |
|----------|---------|---------|
| `DNS_SETUP_MODE` | `wait` | `wait`, `print`, or `webhook` operator workflow |
| `DNS_WEBHOOK_URL` | Empty | Notification endpoint for webhook mode |
| `DNS_WEBHOOK_TOKEN` | Empty | Shared secret used to HMAC-sign webhook payloads |
| `DNS_SETUP_TIMEOUT` | `1800` | Seconds to wait for DNS setup |
| `DNS_SETUP_INTERVAL` | `15` | Seconds between DNS checks |
| `DOH_RESOLVERS` | Google + Cloudflare | Comma-separated DoH resolvers used for record verification |
| `TLSALPN_PORT` | `9443` | Loopback port for the lego ACME responder |
| `TLS_TERMINATE_PORT` | `9444` | Loopback port for the TLS frontend in TLS-ALPN-01 mode |
| `DNS_SETTLE_SECONDS` | `30` | Cache-settle delay before first issuance |
| `RENEW_DAYS_BEFORE` | Client default | Remaining certificate lifetime that triggers renewal |
| `DELEGATION_PROPAGATION_SECONDS` | `120` | Wait after writing delegated challenge TXT records |
| `CERTBOT_TIMEOUT` | Provider-derived | Maximum duration for one Certbot run |

`tls-alpn-01` requires operator-managed DNS and direct CA access to port 443.
It routes to one CVM instance. Wildcard certificates use DNS-01.

## Protocol Support

| Protocol | Default Mode | TLS Passthrough Mode | Egress Traffic |
|----------|--------------|----------------------|----------------|
| HTTP/1.1 | ✅ | ✅ | ✅ |
| HTTP/2 | ✅ (with `g` suffix) | ✅ | ✅ |
| WebSocket | ✅ | ✅ | ✅ |
| TCP | ❌ | ✅ (with `s` suffix) | ✅ |
| UDP | ⚠️  (NAT traversal) | N/A | ✅ |

## Rate Limits

### DNS Providers

| Provider | API Limits | Certificate Speed |
|----------|------------|-------------------|
| Cloudflare | 1200 req/5min | 1-2 minutes |
| Linode | 800 req/hour | 2-5 minutes |
| Namecheap | 50 req/hour | 5-15 minutes |

### Let's Encrypt

| Limit | Rate |
|-------|------|
| Certificates per domain | 50/week |
| Duplicate certificates | 5/week |
| Failed validations | 5/hour per hostname |
